# 合成数据生产线完整流程（含所有疑问点）

## 角色与核心思想

先说清楚这篇论文在解决什么问题。

**Lean 证明饥荒**：想让 LLM 学会写 Lean 4 这种形式化证明，需要的是「定理 + 完整证明」的训练数据。但人类只为极少数定理写过 Lean 证明——写出高质量的机器可验证证明本来就大学数学毕业都难，全世界的 Lean 库（mathlib）也就百万行级别。数据比 Python 代码少几个数量级，模型没得学。

**本文的解法**：不攒人类数据，造一条**合成数据生产线**——用 LLM 把网上亿万条自然语言数学题自动翻译成 Lean 4 定理语句，再让模型+Lean 验证器自动找出正确证明，凑出 **8,066,621 条（约 807 万）**「语句+证明」对来继续训练 DeepSeekMath 7B。

整条流水线里谁在动、谁说了算：

- **DeepSeek-Prover（即 DeepSeekMath-7B 的续训版）**：既当「翻译官」（自然语言→Lean 语句），又当「证明员」（给语句找证明），还兼「质检员」（给语句打分）。
- **Lean 4 验证器**（leanprover/lean4:v4.7.0-rc2）：唯一的裁判，证明对不对它说了算，LLM 说了不算。
- **MMA 数据集**（mathlib 语句 + GPT-4 回译的自然语言）：第一轮冷启动时兼任翻译启蒙老师。
- **反馈闭环**：证明成功的对子再喂回模型续训，循环到涨不动为止。

一句话核心思想：**验证器是免费的真理，那就把 LLM 的生成量堆上去，用验证器筛出金子，再用金子把 LLM 炼强，循环。**

## 全程总览：一道题入 Lean 库的完整旅程

```
互联网抓题(869,659道自然语言题)
        │
        ▼
[阶段一] 自动形式化（Autoformalization）
        │  冷启动:先用MMA数据集教"翻译腔"，
        │  再批量把自然语言题翻译成 Lean 4 语句
        ▼
[阶段二] 质量过滤（Quality Filtering）
        │  ① 模型打分: excellence/good/above average 留，
        │     fair/poor 扔
        │  ② 假设拒绝: 结论换成 False 还证得出来 → 假设自相矛盾 → 扔
        ▼
     得 712,073 条高质量 Lean 语句
        │
        ▼
[阶段三] 语句证明（Statement Proving）
        │  双路并行: 同时证 P 和 ¬P，
        │  谁先证完就停，证出的证明都入库
        ▼
[阶段四] 迭代增强（Iterative Enhancement）
        │  新数据续训 DeepSeek-Prover → 回到阶段一重跑
        ▼
    最终 8,066,621 条(validated) 语句+证明
        │
        ▼
    miniF2F-test pass@64 = 46.3%（GPT-4 是 23.0%）
```

## 阶段一：自动形式化——从一句人话到一条 Lean 定理

### 1.1 题从哪来

作者爬网并清洗，拿到 **869,659 道**高质量自然语言数学题（原文 §3.1）。

**疑问点①：为什么专挑高中和本科竞赛题（初等代数、数论为主），不挑前沿数学？**
两个原因（原文原话逻辑）：一是**这类题条件明确、目标清晰**，好翻译——前沿数学往往需要先定义一堆复杂构造，自动形式化根本啃不动；二是**看似简单但解法未必简单**，照样能构造高质量证明数据。所以选题目标的第零原则是「可自动出题、可自动证明」，不是「够高级」。

### 1.2 翻译官是怎么练出来的

直接拿 DeepSeekMath-Base 7B 去翻译，效果很差（原文原话："Initially, the model struggled"）。解法是**先灌一份「回译数据」做冷启动**：

- 用 **MMA 数据集**（Jiang et al. 2023）：里面是 mathlib 里的 Lean 4 语句，再让 GPT-4 把这些语句**反向翻译回自然语言题目**。也就是说，手里有配对好的「自然语言题目 ↔ Lean 4 语句」。
- 用这份配对数据微调模型，让它先学会「这个领域该怎么说话」。

这里冷启动数据的走向要念一遍才明白：它是**反着造的**——先有 Lean 语句，再让 GPT-4 解释成人话，配成对子。这跟「人写题目再翻成 Lean」的常规思路正好反过来，但训练价值一样——配成对的「人话 ⇄ Lean」数据，不在乎造的时候谁在先。

**疑问点②：为什么不直接让 GPT-4 把 86 万道题都翻好？**
文中没说细节，但逻辑上很清楚：86 万道 × GPT-4 单价，成本不可控；而且**对子的质量不在于谁翻译，在于配对关系本身成不成立**。用 MMA 那少量配对教小模型入门，后面再大规模自产自销，这是标准的「人做种子、模型做规模」路线。具体成本账原文没给，属待核实。

### 1.3 实际翻译用的提示词（原文 §3.1 直接给出）

原文的 prompt 结构（§3.1 直接给出）：

```
Mathematical Problem in Natural Language:
{$informal_statement_with_answers}     ← 原始题目文本
Translate the problem to Lean 4
(only the core declaration):           ← 只要核心声明，不要证明
'''lean4
```

**疑问点③：为什么要"only the core declaration"——不让模型翻题时顺手写证明？**
两个原因：一是这张表里要的是 Lean **语句**（命题），语句翻对了，证明可以交给后续专门的搜索阶段（阶段三）；二是让翻译员兼职写证明，两个任务互相拖累——翻译对了但证明写崩了，整条样本废掉，还没法定位错在哪。

翻译出的 Lean 语句长什么样？原文的示例题型：

```
example (a b : ℝ) :
  Matrix.det ![![1, Real.cos (a - b), Real.cos a],
                ![Real.cos (a - b), 1, Real.cos b],
                ![Real.cos a, Real.cos b, 1]] = 0
```

也就是「题目里的矩阵 → Lean 的 `Matrix.det ![...]` 表达式；题目的『求证行列式为 0』 → `= 0`」。注意这条**只有命题，没有证明**，证明属于阶段三的事。

## 阶段二：质量过滤——Why 86 万条只活下 71 万

自动翻译出来的语句普遍有两个毛病（原文 §3.2 原话），所以过滤分两道工序。

### 2.1 第一道：把"太简单的题"扔掉

第一类毛病是**很多语句过于简单**（原文："many formal statements were overly simplistic"）——简单的语句哪怕证出来，对提升证明能力也没营养。解法是**让 DeepSeek-Prover 自己给语句打分**：

- 先定五档：`excellent / good / above average / fair / poor`。
- 用 **miniF2F-valid 里的例子当 few-shot 样例**给模型看「这题大概什么档」。
- 用 **chain-of-thought**，先分析语句的含金量再给结论。
- 打分留 `excellent / good / above average`，**fair / poor 淘汰**。

人工抽查了打分分布，模型给的分和人类直觉高度一致（原文："closely matched human intuition and expectations"）。

**疑问点④：让模型自己评分，它凭什么比直接把所有题都拿去训更靠谱？**
这里的核心假设不是「模型是好的质检员」，而是「**不用人工**就能把分明显的头部题和尾部题分开」——miniF2F-valid 例子给了校准锚点，CoT 让评分有理有据。就算它不完美，主观题不靠验证器（语句还没到证明那步），模型只能先粗筛。等到阶段三 Lean 验证器兜底客观对错，两道闸各管各的。

### 2.2 第二道：把"前提自相矛盾的题"扔掉

这是一个非常隐蔽的坑。看原文的例子：

```
example (θ : ℝ)
  (h₀ : ∀ z : ℂ, z ^ 2 = -1 ∧ z ^ 3 = -1 ∧ z ^ 6 = 1)   ← 这个假设是假的！
  (h₁ : Real.tan θ = 2 * Real.sqrt 3)
  : θ = 5 * Real.pi / 3
```

`∀ z, z² = -1 ∧ z³ = -1 ∧ z⁶ = 1` 是一个矛盾前提：由 z²=-1 可推出 z⁶ = (z²)³ = (-1)³ = -1，与 z⁶=1 直接冲突。**在 Lean 这种以矛盾律为底座的逻辑里，前提一旦矛盾，"任何结论"都成立（ex falso quodlibet）**，所以这条"定理"数学上毫无营养——再离谱的结论也能"证"出来。

**检测方法：假设拒绝（Hypothesis Rejection）**——把原语句的结论 `θ = ...` 换成 `False`，拿去让模型证：

```
example (θ : ℝ) (h₀ : ...) (h₁ : ...) : False := by
  simpa using h₀ 1        ← 顺理成章地从矛盾假设里导出 False
```

如果 `False` **被证出来**，说明假设（h₀ 等）自相矛盾 → 整条语句是空壳，扔掉。
如果 `False` 证不出来，说明假设至少自洽 → 语句还活着。

用这两道闸洗完，得到 **712,073 条**高质量 Lean 语句（原文 §3.2；过滤前语句总数原文未给，与 86.9 万道题也非一一对应，模型一道题可翻出多条变体——此处待核实）。

**疑问点⑤：把结论换成 False 去证，跟直接证原结论，怎么工作量差这么多？**
证原结论需要模型真的会解 θ；证 False 只需要模型找到假设内部的一处矛盾。**矛盾命题是逻辑上"最容易证"的一类（只要假设里矛盾存在就有机械的 absurd/simp 路径可以走）**，所以这个检测便宜，且只需一条 attempt，不用每次都跑大规模证明搜索。这是把"数学问题"折成"逻辑问题"再检测的典型 trick。

## 阶段三：语句证明——为什么证 P 还要同时证 ¬P

拿到 71 万条语句，下一步是给**每一条**找 Lean 验证器认可的证明。

### 3.1 惊人的浪费参数

传统做法（brute force）：给定语句，反复让模型生成整证直到成功或算力耗尽。本文指出这招在自家数据上要命——**经过质量过滤后，仍有 ≥ 20% 的语句是错的/不可证明**（原文 §3.3 数字，"during large-scale autoformalization, we observed that at least 20% of the formal statements...were incorrect"）。

为什么错这么多？因为题是模型翻译的，翻错、限制条件漏了、前提搞错都可能让命题本身不成立。而**错误的命题在可靠的证明系统内是证不出来的**——这本来是形式逻辑的优势，现在变成了烧算力的坑：证不出来的语句会一直试到超时。

### 3.2 双路证明（Dual Concurrent Proof Searches）

解法：对每条语句 Γ⊢P，**同时**开两条搜索流：

```
             ┌──→ 流 A: 试图证明 Γ ⊢  P（原命题）
语句 Γ ⊢ P ──┤
             └──→ 流 B: 试图证明 Γ ⊢ ¬P（否定）
```

- 任一条先证出来，**整个任务立刻终止**。
- 每条流最多尝试 k 条证明（原文 "attempts up to k proofs"），不到 k 次证出来提前结束。
- 证出来的是哪一边，就**顺带完成了真假判定**：证出 P → 原语句是真命题；证出 ¬P → 原语句是假命题（多半是翻译出错了，但数据照收）。

**疑问点⑥：证出 ¬P 那次，无论哪种证法，"题是错的"这件事怎么变成有用数据？**
因为**证伪一个命题的证明，跟证真一个命题的证明，对模型来说都是「合法的 Lean 训练样本」**。证伪展示的是怎样从某个命题的前提推出矛盾/否定结论，这跟证明一样，是好的推理行为积累。本文利用的是命题与否定之间的**逻辑对称性**：**不管原命题真假，两边的证明都有价值，都收走。**（原文："this dual approach serves as a form of data augmentation, enriching the dataset with both propositions and their negations"）

**疑问点⑦：如果 ¬P 也证不出来呢？**
两条流都试满 k 次都没成功 → 放弃这条语句，不产出任何训练样本（原文没给丢弃比例，待核实）。好在双路最多只烧 2k 次尝试就止损，不会无限烧。

**疑问点⑧：为什么事先不能判断命题真假，非要并行跑？**
因为「命题真假」这件事，**只有证明才能判定**——模型翻译题的时候并不知道自己翻错了，也没有别的廉价手段先验真假。如果先单路证 P、证不出来再回头开 ¬P，用在这个注定失败的语句上的总预算翻了倍；双路并行让两条可能性**同时**探索（原文："Once either the original statement or its negation is proved, the entire proving process is terminated"）。

### 3.3 双路是怎么省算力的（示意推演）

假设一条语句的证明搜索预算 k=10（原文未给具体取值，此处为示意）：

```
旧行为: 只证 P，10 次尝试全失败（因为命题本身是错的）
        → 白烧 10 次生成成本，一无所获，等 Lean 超时

双路:   P 流还在试，¬P 流第 3 次就证出「原命题为假」
        → 立即终止，总支出 ≈ 3 + (P 流已烧的少量次数)
        → 收获 1 条验证过的否定性证明样本
```

对那 ≥20% 的错题，旧行为的花销是「全额预算 + 颗粒无收」，双路是「尽早证伪 + 落袋一条否定样本」。原文没有给具体加速倍率，这里只是把机制算明白。

## 阶段四：迭代增强——把金子炼成更会挖金的铲子

核心循环（原文 §3.4 + §3 首段）：

```
DeepSeek-Prover 生成语句 → 过滤 → 证明 → 收集(语句,证明)对
     ↑                                        │
     └──────── 续训模型 ←───────────────────── ┘
                改进趋缓 → 终止
```

读这个循环要盯住一个点：**每轮的模型比上一轮更强**。

- 第一轮：用 MMA 冷启动过的弱模型翻题，翻出来的语句质量一般，证出来的证明质量一般。
- 第二轮：第一轮证完的数据把模型喂强了，翻题更准、证明更快、质检更狠 → 数据质量又上一层。
- 循环，直到边际改进接近 0。

**疑问点⑨：这算不算自我污染、越练越犬儒？**
Lean 验证器在这里扮演了**外部真值**的角色：不管模型怎么自产自销，**只有 Lean 说 "OK" 的证明样本才能进入训练集**，生成错误只要没骗过验证器，就进不了数据。所以不会出现"模型的错自我强化"这种崩坏路径。这是形式化任务相比自由文本任务的独有福利：verifier 是免费且完美的答案表。

| 表 3 打分过滤 | 高分（excellent/good/above average）训练 | 比训练在低分数据（fair/poor）高出 **4.5%** | §4.3.2 |
| 表 4 迭代轮数 | iteration 0→4 的 test pass@128 | 34.0 → 39.3 → 41.4 → 45.1 → **46.3**，单调涨 | 表 4 |
| 表 5 数据量 | 1k → 8M 条推理数据 | test pass@128：24.18 → **40.16**，数据越大越好 | 表 5 |

**疑问点⑩：iteration 0 就已经 34.0%，比 25.4%（base 裸模）高了 8 个点，这部分收益来自哪？**
原文语境中，iteration 0 的模型已经不是裸 DeepSeekMath-Base：**在正式进循环前，先用 MMA 数据集做过冷启动微调**（见 §3.1），所以 iteration 0 的 34.0/38.1 里有一部分是 MMA 回译数据本身的收益，不全是循环机制的贡献。循环机制本身的贡献看增量：iteration 0→4 把 test pass@128 从 34.0 抬到 46.3（valid 从 38.1 抬到 59.4），5 轮每轮都在涨，直到趋于收敛。

## 所有疑问点速查

| 疑问 | 答案 |
|---|---|
| ① 为什么挑高中/竞赛题？ | 条件明确好翻译，且解法照样有难度可出证明数据 |
| ② 为什么不让 GPT-4 全包翻译？ | 数据量成本；配对关系本身才是关键，人做种子模型做规模 |
| ③ 翻译时为什么不让写证明？ | 语句和证明分开产线，翻译对了证明交给专门的证伪/证明阶段 |
| ④ 模型自己评分靠谱吗？ | 不保底但可规模化，靠 miniF2F few-shot 锚点+CoT 保证一致性 |
| ⑤ 证 False 怎么比证原命题省力？ | 前提矛盾时 False 是逻辑上最好推的结论，找到一处矛盾即可 |
| ⑥ 证出 ¬P 的样本算数据？ | 算，证伪也是合法 Lean 推理行为，是一种数据增强 |
| ⑦ 双路都没证出来怎么办？ | k 次预算耗尽即丢弃，不会无限烧算力 |
| ⑧ 为什么不先判真假再单向？ | 命题真假只有证明才能判定，双路并行平均近半砍掉无效等待 |
| ⑨ 相信 verifier 是不是等于规避自我污染 | 是，Lean 验证器是外部真值，不过关的样本进不了训练集 |
| ⑩ iteration 0 的 34% 怎么来的？ | MMA 冷启动微调带来的底仓收益；循环机制把 34.0 续涨到 46.3 |

## 一句话总括

**从 86.9 万道网上的自然语言数学题出发：先用 MMA 回译数据把 DeepSeekMath-7B 教成翻译官 → 批量翻成 Lean 4 语句 → 用模型评分（丢太简单的）+ 假设拒绝（证 False 锁死自相矛盾前提的）洗成 71.2 万条 → 对每条语句双路并行证 P 和 ¬P、证出一个立即收工（顺带消化掉 ≥20% 错题）→ 拿验证过的(语句,证明)对续训模型、回炉再翻再证 → 数轮迭代后攒出 8,066,621 条数据，把 miniF2F-test 的 pass@64 抬到 46.3%（GPT-4 是 23.0%），FIMO 148 题证出 5 题（GPT-4 颗粒无收）。** 验证器是完美的裁判，模型只负责生成，真值永远对齐 Lean。
