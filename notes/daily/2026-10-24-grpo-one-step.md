PPO 做 RL，要额外养一个**价值模型**（critic），体量通常和策略模型一样大，显存与算力直接翻倍。
DeepSeek-R1 的 GRPO 把这个零件拆了，换成一行不需要碰任何模型的算术。下面是 R1-Zero 一次训练步的完整账。

## 一、设定

| 项 | 值 |
|---|---|
| 起点模型 | DeepSeek-V3-Base（671B MoE，37B 激活） |
| 提示模板 | 只要求 `<think>…</think> <answer>…</answer>`，**不教任何推理方法** |
| 每题采样 | 16 条输出 |
| 奖励 | 规则奖励 = 答案对错 + 格式规范，两项等权，**不含任何神经奖励模型** |
| 训练量 | 10,400 步，每步 32 道不同题（批大小 512） |

奖励全是规则：数学题把答案放进 `\boxed{}` 与标准答案比对，代码题用编译器跑预置测试用例。
故意不用神经 RM——大规模 RL 下神经奖励模型会被"破解"（reward hacking），重训又贵又折腾流水线。

## 二、第 2 步是整篇论文的核心

16 条回答互相当参照系，**不需要价值网络**：

```
r₁..r₁₆ = 16 条回答的规则奖励（如 1 分 / 0 分）
Aᵢ = (rᵢ − mean(r₁,…,r₁₆)) / std(r₁,…,r₁₆)      （原文式 3）
```

就这一行。同一道题里，答得好的 $A>0$（被鼓励），答得差的 $A<0$（被抑制）。

顺手还能推出一个有意思的结论：**如果一道题 16 条全对，所有 $r$ 相同，优势全为 0，没有梯度——这一步等于白跑。**
所以出题难度必须和模型能力匹配：太简单没信号，太难全错也没信号。

## 三、为什么 PPO 明明能用，还要另造 GRPO

原文附录 A.3 给了三条理由：

1. **省一个价值模型。** 除了显存与算力翻倍，更本质的问题是：价值模型的任务是"看到一半的长 CoT 就预测最后的奖励"——
   而长推理里前文常常被后文推翻，这个预测本质上就不好做。
2. **KL 的加法方式不同。** PPO 把逐 token 的 KL 当成稠密奖励加进信号，惩罚的是 KL 累计和，隐含地也在惩罚长回答；
   GRPO 把 KL 的无偏估计量直接加在损失里。做长 CoT 训练时这个差别是致命的——你想让回答变长，PPO 的写法在跟你作对。
3. **少整定一个参数。** 原文图 4 的实测（Coder-V2-Lite）：PPO 的 GAE 系数 λ 需要精调才能接近 GRPO，
   λ 取开源实现默认的 0.95 时明显更差。

## 四、别以为它没有安全带

GRPO 仍然保留 KL 项，并且**每 400 步把参考模型刷新成当前策略**。要训几千步，策略会离初始参考非常远，
定期刷新是在"探索范围"和"训练稳定"之间找平衡。
