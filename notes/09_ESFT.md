# ESFT 完整流程（含所有疑问点）

## 开篇先勘误（以抓到的原文为准）

以下几个流传的说法，抓原文对过之后都不成立，先立正再开讲：

- **副标题不是 "Multilingual Large Language Models"**。arXiv:2407.01906（v2，2024-07-05）的正式标题是 *Let the Expert Stick to His Last: Expert-Specialized Fine-Tuning for **Sparse Architectural** Large Language Models*，EMNLP 2024 Main 收录。没有任何查证到的同名 "Multilingual" 版本。
- **arXiv:2406.15015 与本文毫无关系**。查证结果是 *GraLMatch*（实体匹配/图与语言模型的领域论文），不是 ESFT 的前身，纯编号相近。
- **本文的探测实验不是"先做 MoE 精调基线再探"**。原文的做法是把任务数据直接喂给一个 vanilla 模型（对齐训练完、还没做专项微调的 DeepSeek-V2-Lite），只观察路由分布。"辅助损失、无辅助损失均衡组合出 base、16B×{0,4,6} 之类配比"属于 DeepSeek-V3 技术报告里复用 ESFT 做实验时的口径，本文正文没有这些（本文骨干是 DeepSeek-V2-Lite，全参可训练量 15.7B 的口径见表3）。

## 角色与核心思想

**问题**：想给 MoE 大模型做专项定制（补数学、上法律这类），全参数微调（FFT）能把任务练好，但动了几十亿参数，通用能力集体掉分（原文表2：FFT 平均 58.8 vs vanilla 62.4）；LoRA 省参数但任务能力差得远（44.9 vs FFT 51.0）。

**观察**：MoE 里的专家分工是"专业化"的——同一个任务的 token 天然集中在少数专家手里，不同任务用的专家组合几乎不重叠（原文图2、图3）。既然如此，任务能力就"住在"少数专家里，那定制时**只调这几个专家**，其余全冻死。

**产出**：一个「vanilla 原版 + 若干层被细调的专家」的模型：任务能力接近 FFT，通用能力几乎不掉，存储省约 90%、时间省约 30%（原文摘要与 §5.2）。

**推演里谁在动**：探测阶段只有前向没有训练；ESFT 阶段只有被选中的非共享专家的参数在动；gate、注意力、共享专家、embeddings 全程冻结。

## 推演一：一次探测实验的完整流程

### 第 0 步：准备 vanilla 模型

原文 §4.3：以 DeepSeek-V2-Lite 为骨干（每层 66 个细粒度专家），先在一份**刻意不含数学和代码数据**的对齐数据集上做对齐训练，得到的 checkpoint 称为 vanilla。故意把 Math/Code 压到基础水平（MATH 19.6），是为了后面加专项数据时能清楚看到涨幅。

### 第 1 步：从每个任务喂一小撮数据，只前向、不训练

取 §4.1 的 8 个任务（Math、Code 两个增强类 + Intent、Summary、Law、Translation 四个适应类），把这批数据的 token 依次过 vanilla 模型的 MoE 层，记录每层每个 token 对每个非共享专家的亲和分数（原文式3）：

```
sᵢ,ₜ = Softmaxᵢ( uₜᵀ eᵢ )

uₜ  = 该 token 在本层 MoE 前的隐向量
eᵢ  = 第 i 个专家的质心
     → 每层取 Top-K（本文 66 中激活 8 的口径，含共享专家配比见下文公式）
```

**疑问点①：探的是"精调后"的模型还是"原始"的对齐模型？**
原始的 vanilla。原文 §3.2 的探测就是在对齐训练完的模型上直接喂任务数据看路由，**没有先做 MoE 精调基线**。所以这些专业化是预训练/对齐阶段自发形成的，不是微调造出来的——这一点让后面的结论更硬：专家分工早就在那里，定制只是找到它们、只动它们。

### 第 2 步：统计"归一化 gate 值"的分布

原文 §3.2 第一个观察：把每个专家收到的 gate 值全部加起来除以所有专家的总和，得到它在该任务下的 gate 质量占比，按占比从高到低排序（图2）：

```
     gate 质量占比
100% ┤██
     ┤██
     ┤██░░░░░
     └──────► 专家（按占比降序）
```

**few experts handle most gate values**。**疑问点②：为什么用"gate 值总和"而不是"被选中次数"来刻画集中度？**
gate 值是"选中 + 权重"的乘积，包含了"这个专家接手时有多被信任"的强度信息；纯次数只有命中一档。两个口径原文都造了，探测观察用归一化 gate 值，ESFT 选专家时两个都提供（见下文）。

### 第 3 步：跨任务对比，画"共享 Top-6"热图

原文图3：对每个任务独立抽两份小样本，各自统计每层 token 的 Top-6 专家集合，数两份样本的交集大小，层间取平均，得到任务的"内部一致性"；任务之间的重叠则是"跨一致性"：

```
             Intent  Summary   Law   Trans.   Math   Code
  Intent      ≈6       ≈0       ≈0     ≈0      ≈0     ≈0
  Summary     ≈0       ≈6       ≈0     ≈0      ≈0     ≈0
  Law         ≈0       ≈0       ≈6     ≈0      ≈0     ≈0
  ...
       （对角 ≈ 6，非对角 ≈ 0，原文图3）
```

**对角线 ≈6**：同一任务两次独立采样的专家组合几乎完全重合（所以探测可靠）；**非对角 ≈0**：不同任务的专家组合几乎不换手。两条结论合起来就是 ESFT 的全部赌注：**路由集中在同一任务内、不同任务之间相互独立。**

**疑问点③：图3 为什么盯 Top-6？**
训练/推理时走 top-K 路由，最上面那几个专家承担了绝大部分任务 token。原文附录 E 在 p=0.2 的口径下也是按每层 top-6 的 token 着色分析；用 Top-6 既能代表"这个任务真正吃到东西的专家"，又能防止把长尾专家的噪声计入重叠。

## 推演二：一次 ESFT 微调的完整旅程

### 阶段 0：base 及冻结底本

从 vanilla 出发，把所有参数都视作冻结底本。注意原文的 DeepSeekMoE 结构（式4、式5）：

```
hₜˡ = Σᵢ FFNᵢˢ(uₜˡ)            ← Ks 个共享专家，每个 token 必过，Eq (4)
      + Σᵢ gᵢ,ₜ FFNᵢⁿ(uₜˡ)     ← 非共享专家，gate 里选 Top (K−Ks) 个，Eq (5)
      + uₜˡ
```

**疑问点④：ESFT 到底统筹哪些部分在动？**
原文 §3.3 + 表3口语版：**只有被选中的非共享专家 (Eₛˡ) 可训练**。共享专家、gate、注意力层、embeddings 默认全部冻结。§6.3 用消融验证这是"金钥匙"：只调任务相关非共享专家时通用能力保持最好；一旦开始动共享类参数，通用分就往下掉（见下文数字）。

### 阶段 1：抽样（只为算亲和度，一次前向）

原文 §3.3「Data Sampling」：从任务训练集里随机抽 **32 条拼接样本，每条固定 4096 token**，即约 2^17≈131072 个 token，专门用于算亲和度。附录 C 做了稳健性检验：从同一任务独立抽两份样本，看它们各自 Top-6 专家的平均交集，随样本量增加在 2^17 处已收敛（图8）。

**疑问点⑤：32 条就知道该调谁，样本太少不可信？**
这不是"让模型学会任务"的样本，只是"给路由画像"的样本。图3 显示同一任务两组独立数据 Top-6 集合几乎重合，说明"谁被用到"对任务来说是稳定属性；附录 C 进一步量化了这种稳定性在 2^17 token 就饱和。选专家是一次性开销，不是训练本身。

### 阶段 2：给每层每专家打分（两个可选分数）

原文式6、式7：

```
平均 gate 分 (ESFT-Gate):
  gᵢˡ = (1/Nₛ) Σⱼ (1/Lⱼ) Σₖ gᵢ,ₖˡ        ← 对所有样本 token 的 gate 值求平均
token 选择比 (ESFT-Token):
  rᵢˡ = (1/Nₛ) Σⱼ (1/Lⱼ) Σₖ 𝟙(gᵢ,ₖˡ > 0) / K   ← 命中率除以 K
```

**疑问点⑥：两个分数差在哪？什么时候该用哪个？**
Gate 分带权重：一个专家被选中且很高置信才高分。Token 比只数命中次数、不问权重，且除以 K 把"每次命中在 K 个名额里占的一个坑"归一成任务可信口径，让两个分数落在可比尺度上。实验上两者都行，视任务挑（原文两个变体分开报，任务表见下文）：ESFT-Token 通用能力保持更稳（表2 均值 61.5 vs 60.6），ESFT-Gate 任务上限略高（表1 均值 50.2 vs 49.4）。

### 阶段 3：按累积分数选专家（阈值 p）

原文式8：每层把专家按分数从高到低累加，凑够阈值 p 就停，选中集记为 Eₛˡ：

```
Σ_{i∈Eₛˡ} Rᵢˡ ≥ p

主实验: ESFT-Gate  p=0.1
        ESFT-Token p=0.2
```

**疑问点⑦：p 怎么定的？选多了会怎样？**
原文 §6.2 用 Math 任务扫 p 发现曲线饱和：p≥0.2（Token）/ 0.1（Gate）之后收益基本不变，说明**超出这个质量阈值的专家对任务并不真正相关**。这也隐含一个反直觉点：任务信息不在长尾均匀分布，而在头部若干专家里。

### 阶段 4：微调

```
              ┌───────────────────┐
任务数据 ──►  │ gate / 共享专家、注意力、 │  ← 全部 frozen（梯度被 mask）
(掺对齐数据)  │ embeddings、其余非共享专家 │
              └───────────────────┘
              ┌───────────────────┐
        ──►  │ Eₛˡ 被选中的非共享专家     │  ← 可训练，lr = 1e-5
              └───────────────────┘
路由照旧: token 仍可自由路由到任何专家；不过 gate 保持不变
算力：2 节点 × 8×A100；batch 32；seq 4096；500 步上限，每 100 步评估
```

**疑问点⑧：路由不着特制的 mask、gate 也不改，被焖住的专家仍然接 token，这安全吗？**
安全，而且这正是这个设计干净之处：非被选中的专家权重没动、gate 没动，所以它们输出依旧等于训练前那份"公共前文管道"，不会把其他任务能力的输入带坏。被改变的只有 Eₛˡ 里的权重，而它们在原任务里本来就是任务 token 的主要去处。

**疑问点⑨：都想改其他专家好理解，为什么 gate 不改？**
gate 在这里既是决策器又是冻结底本。如果重新调 gate，等于把"所有权重的分工地图"一起改写，任务外 token 也会跟着重新路由，通用能力立刻有暴露面。原文式5 的 Top 还是"token 亲和度"决定，训练用路由和推理用路由都是这个；**训练和推理时 token 都可被分到任何专家（原文 §3.3 原话）**，只是每层能被更新的只有 Eₛˡ。折射到底就是一个决策：为社会赚取通用能力而不动"分工地图"，为掌握任务而只动"分工地图上的热点节点"。

**疑问点⑩：推理部署时怎么组合？低显存加载也动吗？**
按原文口径：推理时**照常用自己的 gate 自由路由**，只是 Eₛˡ 那些专家的权重被换成了微调完的版本，其他专家原样驻留，序列喂进去即可。这样"vanilla + 替换版专家"组合出一个新模型。文中未给权重底配加载方案（比如只把任务相关专家算进本地显存的做法）；**那个"只加载被调专家的低配显存版"是后续相关报道/复用语境里的玩法，本文没有写，属于延伸裁量（待核实），不要划等号。**

### 阶段 5：任务能力与通用能力各自怎么进来

这个阶段的输入是任务数据，但原文所有方法都**按 1:1 掺了一份对齐数据**（§4.3），这是一个关键差异点：FFT/LoRA 必须靠掺对齐数据续命通用能力（附录 F），而 ESFT **不掺也稳**（甚至更好，附录 F）。原因是结构性的：FFT/LoRA 的可训练参数贯穿全模型，任务梯度会"顺路"冲刷所有公共管道；ESFT 的可训练面被限制在任务专属专家内，公共管道物理上不接收任务梯度。

## 所有疑问点速查

| 疑问 | 答案 |
|---|---|
| 探的是精调后模型还是 vanilla？ | vanilla，对齐完直接喂任务数据看路由，无需先有精调基线 |
| 为什么敢赌冻结能动？ | 路由集中（同任务少数专家吃大头）+ 任务间互斥（图2、图3） |
| gate 值怎么归一化？ | 每专家收到 gate 总和 / 所有专家总和，降序排（图2） |
| 图3 为什么堵 Top-6？ | 任务 token 的主去处，且避免长尾噪声；附录 E也 用 top-6 分析 |
| ESFT 只动谁？共享专家动吗？ | 默认只动任务相关非共享专家；共享专家动不动由策略定（表3） |
| 32 条样本就敢选专家？ | 选专家是"画像"不是"学会任务"，2^17 token 足够稳（附录 C 图8） |
| Gate 分和 Token 比差在哪？ | 一个带权、一个只数命中且除以 K 归一，二者按任务二选一 |
| p 的作用？选多了会怎样？ | 累积分数阈值；饱和（Token 0.2 / Gate 0.1）说明长尾无关 |
| 被冻住的专家还接 token，安全吗？ | 权重和 gate 都没动，输出仍是老的"公共前文"，不会带坏通用 |
| 为什么 gate 不动？ | 动 gate 等于重写分工地图，任务外 token 路由跟着抖动 |
| 推理时怎么合并多任务专家？ | 本篇按"一次定制一套模型"口径：vanilla + 替换版专家；多任务组合属延伸（原文未展开） |
| 为什么 FFT/LoRA 通用掉分、ESFT 几乎不掉？ | 任务梯度一旦流经共享参数就伤通用（表3）；ESFT 物理隔绝 |
| 掺对齐数据是不是一族方法通用？ | FFT/LoRA 必须掺；ESFT 不掺也稳，甚至略好（附录 F） |
| LoRA 也是 PEFT，为什么差很多？ | 参数省但任务上限低（44.9），改动碰到共享参数反而更伤通用 |

## 一句话总括

**一次 ESFT 定制 = 探测（把任务 token 喂 vanilla、看每层 gate 集中度和任务间互斥）→ 选择（32 条×4096 的抽样集足够稳，用平均 gate 分或 token 选择比给专家打分、按累积分数阈值 p 选出少数专家，主实验 p=0.1/0.2）→ 微调（gate/共享专家/注意力/嵌入/其余火箭全冻死，只放开被选中的非共享专家细调）→ 部署（推理路由照旧，被选专家权重替换成细调版）。** 整个方法的成立性不靠工程巧合，而靠一个天然的架构事实：细粒度 MoE 的专家早就按任务专业化了，定制只需要"让对的专家继续干对的事"。
