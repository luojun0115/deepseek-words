# Janus-Pro 三维扩展完整流程（含所有疑问点）

## 角色与核心思想

- **Janus-Pro 不是新架构论文**。原文 §2.1 开门见山：架构与 Janus 完全相同——「The architecture of Janus-Pro ... is the same as Janus」。核心设计不变：**解耦视觉编码**，理解走 SigLIP 语义编码器、生成走 VQ tokenizer 离散 ID，两路各自经 Adapter 汇入同一个自回归 Transformer。
- 升级只发生在三维（原摘要逐字）：**① 优化训练配方；② 扩充训练数据；③ 模型扩到更大尺寸**。也就是标题里的 "Data and Model Scaling"。
- 整篇要回答的问题：**一个已定型的架构、两个互相打架的目标（理解要语义、生成要像素细节），不改架构，能把两边同时推到 SOTA 吗？** 结论先给出：能——GenEval 0.80、MMBench 79.2（均为 7B），同时超过 Janus 和一批专用模型。

**疑问点①：三处升级一处都不碰架构，提升空间从哪来？**
Janus 当时只在 1.5B 底座上验证过「解耦设计可行」这个命题，数据少、容量小，留下三笔已知的债（原文 Intro 逐条点名）：短提示文生图质量差、文生图质量不稳定、理解分数平庸。三维升级分别还债——**配方**还「训练预算花错地方」的债，**数据**还「见过太少 + 真实数据太脏」的债，**规模**还「容量不够」的债。债不是架构欠的，所以不用改架构就能还。

## 阶段零：地基长什么样（架构，一字未改，但要看懂它）

```
                         ┌──────────── 统一 Transformer（DeepSeek-LLM）────────────┐
 理解路: 图像 → SigLIP-Large-Patch16-384 → 语义特征 →[展平成一维]→ 理解Adapter(2层MLP)→┤
 生成路: 图像 → VQ tokenizer(codebook 16384, 16×下采样) → 离散ID序列 →[展平]→ 生成Adapter(2层MLP) →┤
                                              LLM 内置文本预测头 ← 文本
                                              另设图像预测头(随机初始化) ← 生成时 LLM 输出 ID 概率
```

- 两路 Adapter 都是**两层 MLP**（§3.1）。所有图像统一缩放到 **384×384**（同节）。
- 这套「语义塔 + 离散塔」就是 Janus 的核心遗产：理解不欠生成的账、生成不欠理解的账，Transformer 只负责把两路序列统一地「下一 token 化」。

**疑问点②：生成路为什么要一个额外的「图像预测头」？**
LLM 自带的预测头分布是文本词表的，输的是文字 token；生成时 LLM 要吐的是 VQ 图像 ID（codebook 16,384 个），词表撞不在一起就另开一个头（原文 §2.1："we also utilize a randomly initialized prediction head for image predictions"）。两个头共享同一个 LLM 主体——**解耦只解到编码层，不把 Transformer 撕成两半**，这正是「统一」二字的立足点。

## 阶段一：训练配方的三处手术（§2.2）

旧 Janus 是三段式：Stage I 训 Adapter + ImageHead → Stage II 统一预训练（除理解编码器和生成编码器外全解锁）→ Stage III SFT 并解锁理解编码器。Pro 保留骨架，动刀三处：

```
        Janus 旧配方                                   Janus-Pro 新配方
Stage I   训 Adapter + ImageHead（步数被压短）   →  Stage I   步数加长，ImageNet 集中练够
   （T2I 的「像素依赖」学费记在 Stage II）           （LLM 冻结也能学会像素依赖）
Stage II  统一预训练，T2I 部分学 PixArt 两段式：  →  Stage II  砍掉 ImageNet，T2I 直接用
   66.67% 步数在 ImageNet(类别名作提示)上、          正常文生图数据（密集描述）
   其余约 33.33% 在正常文生图数据上                  → 训练效率与整体性能双升
Stage III SFT，数据配比 多模态:纯文本:T2I = 7:3:10 → Stage III 配比改为 5:1:4
```

**手术 1 —— Stage I 加长**：原文发现，跟着 PixArt 把「ImageNet 建模像素依赖」放在 Stage II 是次优的、算力浪费明显。改法是把 Stage I 的训练步数加长，**ImageNet 这份学费在 Stage I 就一次性交清**。关键发现（原文引述）：即使 LLM 参数全程冻结，模型也能有效建模像素依赖、依据类别名生成合理图像。

**疑问点③：LLM 都冻结了，光训 Adapter + ImageHead 就能学会「生成」？**
能，但要认清 Stage I 教的是什么。ImageNet 生成只需「类别名的语义槽 + 像素依赖」（局部纹理、构图连贯），这部分容量需求很小、完全在 Adapter + ImageHead 的表达能力内；而「密集长描述 → 语义图」这种需要大容量语义推理的能力，交给后面解锁 LLM 的 Stage II。**先把便宜的学和贵的学分开，便宜的学就不必占用贵的学习容量**——这正是把 ImageNet 从 Stage II 挪到 Stage I 的账面逻辑。

**疑问点④：那旧配方到底浪费在哪？**
旧配方把 66.67% 的 Stage II 文生图步数花在 ImageNet 上，而 Stage II 里 LLM 是解锁的——**让一个 7B 级别的语言模型去学 ImageNet 类别名这种低熵任务**，同样的步数本可以加工信息密度高得多的密集描述数据。挪走这段后，Stage II 的每一步都在喂「真正的 T2I 数据」。

**手术 2 —— Stage II 聚焦**：Stage II 不再掺 ImageNet，直接用正常文生图数据训练密集描述生成。原文结论：这让 Stage II 的文生图数据利用效率更高，训练效率与整体表现都变好。

**手术 3 —— Stage III 配比 7:3:10 → 5:1:4**：三类数据（多模态 : 纯文本 : 文生图）再平衡。原文的观察是：**略微下调文生图占比，可以在保持较强生成能力的同时提升多模态理解**。直觉账：T2I 组合目标与理解目标在 Stage III 冲突最尖锐，减掉的多余份额不再两败俱伤；而生成能力有 Stage II 的底子在，禁得起这一减。

**疑问点⑤：T2I 从 10 砍到 4，生成不怕垮吗？**
论文只给现象不给消融：「保持强生成 + 理解更好」。可以对照的数据是 GenEval：Janus 0.61 → Pro-1B 0.73 → Pro-7B 0.80（原文表4）——配比下调与生成上涨同时发生，说明生成的主引擎在于 Stage II 收益与数据质量，Stage III 那点配比不是命脉。

## 阶段二：数据扩容的两条管线（§2.3）

**理解线**：
- Stage II 预训练数据参照 DeepSeek-VL2 **新增约 9,000 万样本**：图像描述类（如 YFCC）+ 表格/图表/文档理解类（如 Docmatix）。
- Stage III SFT 数据同样引入 DeepSeek-VL2 的数据集：MEME 理解、**中文对话数据**、提升对话体验的数据集。原文：显著扩展能力面、丰富多任务处理、改善对话体验。

**生成线**：
- 诊断：旧 Janus 用的真实世界数据**质量差、噪声大**，导致文生图输出不稳定、审美差。
- 药方：**新增约 7,200 万条合成美尽数据**，使统一预训练阶段**真实 : 合成 = 1:1**。合成数据的提示词是公开的（如 Midjourney prompts 数据集，原文引 [43]）。
- 效果（原文原话）：在合成数据上训练**收敛更快**，文生图输出更稳定，审美质量显著提升。

**疑问点⑥：合成数据凭什么让生成「又快又稳又好看」？**
原文给了因果链：真实数据脏（图文错配、审美不一致）→ 学习信号噪声大 → 输出不稳定、审美漂移。合成数据相反：提示词公开可得、图文高度对齐、审美风格一致 → 同样的梯度步数学到的信号更干净。注意原文**没有做「全合成 vs 1:1」的单变量消融**，1:1 是工程定值，我们只能确认「混入 72M 合成数据有效」，不能确认「越多越好」。

## 阶段三：模型扩展 1.5B → 7B（§2.4 + 原文表1）

底座是 DeepSeek-LLM（§3.1），最大序列长度 4096。原文表1 的骨架对比：

| 项 | Janus-Pro-1B | Janus-Pro-7B |
|---|---|---|
| 词表 | 100K | 100K |
| Embedding | 2048 | 4096 |
| 上下文窗口 | 4096 | 4096 |
| 注意力头 | 16 | 32 |
| 层数 | 24 | 30 |

原文的核心观察：**换大 LLM 后，理解与生成两条线的 loss 收敛速度都显著快于小模型**——这被当作「解耦设计可扩展」的直接证据。

**疑问点⑦：Janus-Pro-1B 名字叫 1B，为什么底座其实是 1.5B？**
型号名与底座参数是两回事：原文表3 里 # LLM Params 一栏给 Janus-Pro-1B 标的是 **1.5B**（与旧 Janus 同为 1.5B LLM），"1B" 只是产品线命名。所以「Janus（1.5B）vs Janus-Pro-1B（1.5B）」才是**同规模、纯配方+纯数据对照**；「Pro-1B vs Pro-7B」才展示**纯规模效应**。看数字时必须分清这两条对照轴。

## 阶段四：一次参数扩展后，两个维度各自变多大（对照推演）

把原文表3/表4/表5 的数字排成两条增长轴：

```
理解轴（1.5B底座 → 7B底座，均为 Pro）
  POPE    86.2 → 87.4   (+1.2)        GQA   59.3 → 62.0   (+2.7)
  MME-P  1444.0 → 1567.1 (+123.1)     MMMU  36.3 → 41.0   (+4.7)
  MMB     75.5 → 79.2   (+3.7)        MM-Vet 39.8 → 50.0  (+10.2)
  SEED    68.3 → 72.1   (+3.8)
  → 各榜普涨，且越难的榜涨得越多（MM-Vet +10.2、MMMU +4.7）

生成轴（1.5B底座 → 7B底座，均为 Pro）
  GenEval    0.73 → 0.80   (+0.07)
  DPG-Bench 82.63 → 84.19  (+1.56)
  → 涨，但幅度明显平缓，DPG 几乎持平
```

**疑问点⑧：为什么理解对规模的弹性远大于生成？**
拆开两条贡献链看：GenEval 上 Janus 0.61 → Pro-1B 0.73，**+0.12 完全来自配方与数据（架构零改动、参数零增加）**；再往上 7B 只再贡献 +0.07。也就是说生成侧的收益大头是「学费花对地方 + 数据说干净话」带来的，剩余部分才归参数。理解侧则是纯参数吃香——容量直接决定读图语义的上限。**生成瓶颈更多在训练信号的「质」，理解瓶颈更多在参数的「量」。** 原文只陈述了「两条 loss 都收敛更快」这一现象，上面的拆账是按表格数字做的推演，论文未做过这条归因消融。

## 阶段五：实验成绩单（§3.3，全部抄自原文表格）

**训练代价**（§3.1 + 原文表2）：三段步数 20K / 360K / 80K（1B）与 20K / 360K / 40K（7B），Stage II 采用早停、实际停在 **270K** 步；学习率三段 1.0×10⁻³ / 1.0×10⁻⁴ / 4.0×10⁻⁵，常值调度，AdamW(β₁=0.9, β₂=0.95)；三段数据配比 1:0:3 → 2:3:5 → 5:1:4。训练在 HAI-LLM 上进行：1.5B 花约 **9 天 / 16 节点**，7B 花约 **14 天 / 32 节点**，每节点 8×A100(40GB)。

**理解**（原文表3，Janus-Pro-7B vs 关键对手）：

| 模型 | #LLM | MMB | MMMU | MM-Vet | MME-P |
|---|---|---|---|---|---|
| Janus | 1.5B | 69.4 | 30.5 | 34.3 | 1338.0 |
| TokenFlow-XL | 13B | 68.9 | 38.7 | 40.7 | 1545.9 |
| MetaMorph | 8B | 75.2 | – | – | – |
| **Janus-Pro-1B** | 1.5B | **75.5** | **36.3** | **39.8** | 1444.0 |
| **Janus-Pro-7B** | 7B | **79.2** | **41.0** | **50.0** | 1567.1 |

原文结论：除 GQA 外，7B 几乎全面优于 13B 的 TokenFlow-XL；Intro 直说 79.2 超过 Janus(69.4)、TokenFlow(68.9)、MetaMorph(75.2)。

**生成 · GenEval**（原文表4，总分为准）：

| 模型 | Overall | Counting | Position |
|---|---|---|---|
| SDXL（仅生成） | 0.55 | 0.39 | 0.15 |
| DALL-E 3 | 0.67 | 0.47 | 0.43 |
| SD3-Medium | 0.74 | 0.72 | 0.33 |
| Transfusion（统一） | 0.63 | – | – |
| Chameleon（统一） | 0.39 | – | – |
| Janus | 0.61 | 0.30 | 0.46 |
| **Janus-Pro-7B** | **0.80** | **0.59** | **0.79** |

7B 六个分项：单物体 0.99 / 两物体 0.89 / 计数 0.59 / 颜色 0.90 / 位置 0.79 / 颜色归因 0.66，总分 0.80 压过全部统一与专用模型。**DPG-Bench**（原文表5）：7B 84.19，同样超过表中所有方法（DALL-E 3 83.50、SD3-Medium 84.08）。

**疑问点⑨：GenEval 总分 0.80 里最弱的 Counting 只有 0.59，为什么还敢叫 SOTA？**
看相对数：Counting 这个分项是全榜集体洼地（SDXL 0.39、PixArt-α 0.44、DALL-E 3 0.47），Janus-Pro 的 0.59 已经是该分项最高一档；Position 0.79 更是把 SDS 全家（15%–43%）甩开一个身位。离散 token 自回归天然把「几个 / 哪里」变成可数算术题，这正是解耦离散生成路的长板——总分 0.80 是六项均衡后的结果，不是单项堆出来的。

**疑问点⑩：同样统一路线，为什么 Chameleon 只有 0.39，Janus-Pro 冲到 0.80？**
对照点是「解耦」这个设计决策：Chameleon 单一视觉编码通吃理解与生成，表征需求冲突；Janus 系解耦后中间可以打印（可核查的空间）——生成路上 16× 下采样、codebook 16384 的 VQ 编码只关心「能重建」，不影响理解路的 384 高分辨率语义塔（均出自 §3.1 与 §2.1）。原文 §3.3 的归因（原话）：解耦视觉编码缓解两任务冲突，是理解最优的直接原因；同一归因覆盖生成侧。论文未针对 Chameleon 做逐项消融，此回答以原文表 3/4 的并列数字与 §3.3 归因句为准。

## 局限（原文 §4 结论自述）

- 理解侧：输入分辨率封顶 **384×384**，影响 OCR 等细粒度任务。
- 生成侧：低分辨率 + VQ tokenizer 的重建损失，图像语义丰富但**缺微细细节**（如占画面很小的脸部区域欠细节）。
- 出路（原文明说）：提高图像分辨率。

## 全局数据流总表

| 阶段 | 谁在动 | 数据 | 关键产出 | 出处 |
|---|---|---|---|---|
| Stage I | Adapter + ImageHead（LLM 冻结） | ImageNet（配比 1:0:3） | 像素依赖、类别名生成能力 | §2.2、表2 |
| Stage II | 全模型除两个编码器 | 多模态+纯文本+T2I（2:3:5），含 +90M 理解新数据、+72M 合成美尽数据 | 统一预训练权重（270K 步早停） | §2.3、§3.1 |
| Stage III | SFT + 解锁理解编码器 | 配比 5:1:4，含 MEME/中文对话 | 最终对话与生成模型 | §2.2、§2.3 |
| 规模轴 | 同配方重跑 | – | 1.5B 与 7B 两档权重 | §2.4 |
| 评估 | – | 表3 理解 / 表4 GenEval / 表5 DPG | MMB 79.2、GenEval 0.80、DPG 84.19 | §3.3 |

一句话记住耗材：**9,000 万理解新样本 + 7,200 万合成美尽数据 + 底座从 1.5B 换到 7B + 三个训练阶段动三刀**，其余一切照旧。

## 所有疑问点速查

| 疑问 | 答案 |
|---|---|
| 不改架构哪来提升？ | 还三笔债：配方（预算错位）、数据（少+脏）、规模（容量小） |
| 生成要另设图像预测头？ | LLM 自带头只输文本词表，VQ ID（16,384）需要专属头，主体共享 |
| LLM 冻结也能学生成？ | Stage I 只需类别名语义槽+像素依赖，容量需求小，Adapter+ImageHead 够用 |
| 旧配方浪费在哪？ | 66.67% 的 Stage II 文生图步数喂给低熵的 ImageNet，挤占密集描述数据的份额 |
| T2I 配比 10→4 生成不垮？ | 生成主引擎在 Stage II 收益+数据质量；Janus 0.61→Pro-1B 0.73 同时发生 |
| 合成数据为何快稳美？ | 提示公开、图文对齐、审美一致 → 信号干净；但 1:1 无单变量消融支撑 |
| 1B 型号底座是啥？ | 表3 实标 1.5B；"1B" 是产品线名，对照轴要分清同规模轴与规模轴 |
| 规模涨了谁受益更多？ | 理解普涨且难榜大涨；生成 +0.07 平缓——生成瓶颈在数据质，理解瓶颈在参数量 |
| Counting 0.59 低为何还吹？ | 该分项全榜洼地（SDXL 0.39），离散自回归长板，Position 0.79 同理 |
| Chameleon 为何垫底 0.39？ | 单编码器任务冲突 vs 解耦；归因句见 §3.3，未做逐项消融 |

---

## 一句话总括

**架构原封不动，三刀到位：把 ImageNet 像素依赖学费从 Stage II 挪进 Stage I 并把学费交足、Stage II 只喂真正的文生图数据、Stage III 配比从 7:3:10 调到 5:1:4；数据侧加 9,000 万理解样本与 7,200 万合成美尽数据（真实:合成=1:1）；底座 1.5B→7B。** 结果：理解 MMB 79.2 / MM-Vet 50.0、生成 GenEval 0.80 / DPG 84.19 双线越 SOTA，且回答了 Janus 留下的问题——解耦设计经受住了规模检验。遗留：384 分辨率封顶。
